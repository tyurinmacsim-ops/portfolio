# VPN Telegram Admin Bot

Обезличенный портфельный пример личного VPN-контура на небольшом VPS: Telegram-бот на Python управляет доступом небольшой группы пользователей, а VPN остаётся отдельным сервисом `Xray + Nginx`.

Решение рассчитано на личное использование и примерно 5 пользователей. Это не тяжёлая панель и не Kubernetes-стек: `long polling`, SQLite, systemd и один небольшой privileged helper.

## Что демонстрирует

- закрытый семейный onboarding: одноразовая ссылка-приглашение → короткая анкета → ручное approve/reject владельцем;
- русскоязычный Telegram-интерфейс: выдача одного бессрочного профиля на человека, QR-импорт для Happ на телефоне и инструкции для AmneziaVPN на ПК;
- выдачу VLESS-ключа также текстовым файлом для импорта в AmneziaVPN;
- объяснение раздельного туннелирования: приложения Госуслуг/VK можно исключить из VPN в AmneziaVPN на Windows, а для сайтов в браузере нужен отдельный браузер без VPN;
- проверку административного allowlist по Telegram ID;
- безопасную выдачу профиля `VLESS + WS + TLS` через приватный чат;
- паттерн заявок в канал: approve/reject → eligibility → self-service activation;
- статус VPS, nginx и Xray через фиксированный helper;
- SQLite для пользователей, сроков, аудита и выданных профилей;
- изоляцию systemd-сервиса и минимальный `sudoers` allowlist;
- Xray только на `127.0.0.1:10000`, TLS и WebSocket reverse proxy в nginx;
- backup/validate/reload как обязательный workflow перед изменением Xray.

## Пользовательский поток

1. Владелец создаёт одноразовую ссылку и отправляет её конкретному родственнику.
2. Родственник представляет себя в короткой анкете; владелец сверяет человека в знакомом личном чате и одобряет заявку.
3. Бот создаёт персональный VLESS-профиль. Он не истекает сам и остаётся в приложении до ручного отзыва владельцем.
4. На телефоне бот отправляет QR-код, сформированный только в памяти, и резервную VLESS-ссылку. На ПК — текстовый ключ и `.txt`-файл.
5. Владелец может посмотреть список, временно отключить или отозвать профиль; отзыв удаляет клиента и из Xray, и из учёта бота.

## Операционные выводы

- Система считает выдачу успешной только после изменения Xray и фиксации записи в SQLite; при ошибке не оставляет «полувыданный» профиль.
- `systemd`-изоляция не должна мешать ровно тем операциям, которые выполняет ограниченный root helper. Поэтому он получает доступ только к каталогу состояния бота и bind-mounted конфигурации Xray, а не к домашним каталогам или Docker socket бота.
- `NoNewPrivileges=yes` здесь неприменим: helper вызывается через `sudo`. Вместо этого граница строится из отдельного пользователя, точечного `sudoers`, allowlist действий, проверки аргументов и отсутствия `shell=True`.
- Перед деплоем проверяются импорты, unit-тесты, перезапуск сервиса и его состояние. Ошибка выдачи не маскируется как успешная активация.

## Архитектура

```text
Пользователь -> заявка в Telegram-канал -> одобрение владельцем
                                      -> личный Telegram-бот
                                      -> SQLite (доступы и аудит)
                                      -> ограниченный root helper
                                      -> Xray config / nginx status

VPN-клиент -> HTTPS :443 /vpn-ws -> nginx -> 127.0.0.1:10000 -> Xray
```

## Безопасность

- В git нет токенов, доменов, IP, UUID, реальных QR-кодов, клиентских ссылок, логов или TLS-ключей.
- Сам бот не добавляется в группу `docker` и не получает общий root/SSH-доступ.
- Helper принимает только заранее заданные действия и не использует `shell=True`.
- Чувствительный профиль выдаётся только в личный чат с `protect_content=True`; QR создаётся в памяти, а в audit log попадает только результат операции.
- Для полного падения VPS нужен независимый внешний HTTP/TCP мониторинг: внутренний бот в этот момент не сможет отправить alert.

## Состав

- `app/` — минимальный async Python sample с русскими сообщениями.
- `scripts/vpn-bot-helper.py` — пример root-owned status helper.
- `systemd/` — unit и точечный sudoers allowlist.
- `deploy/` — localhost-only Xray и nginx WebSocket location.
- `.env.example` — только placeholder-переменные.
- `tests/` — проверка параметров выдаваемого WS+TLS профиля.

## Граница примера

В рабочем варианте выдача/отзыв клиента выполняются транзакционно: lock → backup конфигурации → валидация Xray → атомарное применение → health check → rollback при ошибке. В этом публичном артефакте не публикуются реальные команды, реквизиты или действующие профили.
